# INC-004 — Interrupted incremental load: release decision

**Scenario:** An overnight orders load stops after the first record of batch 02.

**At-risk behaviors:** Partial commits, duplicate records on replay, stale version overwrites, omitted late-arriving orders, or conflicting updates.

**Controlled evidence expected from tests:**
- The first batch is replayable without any change in keys, versions or amounts.
- Interruption during batch 02 raises an exception and the before/after target snapshots are identical.
- Clean retry then updates R-2 and inserts R-3 exactly once.
- Late-arrival batch updates R-1 to version 2 and inserts R-4.
- Stale prior batches do not overwrite newer versions.
- Same-version conflicting values are rejected and rolled back.
- Final independent oracle contains four orders and $48.00.

**Decision:** Hold reporting while recovery is incomplete or unverified. Approve the bounded synthetic test scenario only after replay, atomicity and final-state reconciliation checks pass. The tests demonstrate transaction-level behavior, **not** a guarantee of operational recovery in all deployment environments.
