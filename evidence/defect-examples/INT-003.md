# INT-003 — Schema and relational integrity gate

**Classification:** Synthetic learning case. **Decision:** Hold incompatible or invalid extract pending source correction or approved contract change.

## Reproduction

`python -m pytest -q tests/test_integrity.py`

The clean and additive fixtures are accepted. The missing and broken fixtures are deliberately rejected, with the following exact evidence:

- `missing`: `MISSING_COLUMN customers country`
- `broken`: `DUPLICATE_KEY customers:3 C-1`
- `broken`: `NULL_REQUIRED customers:4 name`
- `broken`: `ORPHAN_FK orders:3 C-404`
- `broken`: `DUPLICATE_KEY orders:4 I-2`
- `broken`: `INVALID_TYPE orders:4 amount_cents`

## Analysis

An added optional language field is acceptable under INT-001, but dropping required `country` violates the receiving schema contract. Duplicate keys threaten deterministic identity, a missing name threatens report completeness, an orphan foreign key breaks customer-order relationships, and non-integer amounts violate the reporting type contract.

## Release recommendation

Do not publish the incompatible or invalid extracts into downstream curated reporting. Preserve failing rows and finding codes, coordinate correction or a separately reviewed contract revision, rerun validation, and retain accepted evidence. A green pytest run here proves detection behavior, **not** acceptance of the intentionally broken data.
